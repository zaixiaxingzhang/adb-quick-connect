# 无线调试快速连接工具

一个 Windows 上的 Android 无线调试（Wi-Fi ADB）助手，**核心就一件事：把 adb 连上，越快越好。**

电脑自动生成**二维码 + 配对码**，手机扫一下就完成配对并自动连接；启动时后台静默扫描已配对过的设备直接连上，配对 / 连接 / 断开 / 装 APK 一条龙，全程一条 adb 命令都能看见（执行前会打印出来，方便你核对或自己复制到终端跑）。

内置 Google 官方 adb（`platform-tools/`），开箱即用。

```
================================================
        无线调试快速连接工具
================================================
  [1] 扫码配对(推荐)   电脑出二维码，手机扫码
  [2] 手动配对         输入手机显示的配对码
  [3] 连接设备         自动发现 / 设备库 / 手动
  [4] 设备列表         adb devices -l
  [5] 断开设备         adb disconnect
  [6] 设备库管理       重命名 / 删除
  [7] 安装APK          全屏拖放，拖进去就装
  [8] ADB设置          选adb路径 / 版本 / 重启
  [9] adb shell        进入交互式终端
  [0] 退出（自动清理 adb 后台进程）
------------------------------------------------
```

---

## 为什么用它

| 痛点 | 这个工具的解法 |
|---|---|
| 每次开无线调试，端口都变，还要手动 `adb connect` | 记住配对过的设备，下次**启动即自动连上**（后台静默进行，不打断你操作） |
| 想连设备还得去手机里翻 IP 和端口 | **电脑出二维码，手机扫一下就配对 + 自动连接** |
| 同一台手机在 `adb devices` 里冒出**两条记录**，`adb shell` 还要 `-s` 指定 | 已从根上修好（禁用 adb 自带的 mDNS 自动连接 + 自动清理重复/失效记录），一台手机只留一条 |
| 想装个 APK 还要敲一长串 `adb install -r ...` | **[7] 全屏拖放模式：把 apk 文件拖进窗口就装** |
| 退出后 adb 服务还挂着一堆进程 | 退出（含直接点窗口右上角 X）自动 `adb kill-server` |

## 快速开始

1. 双击 **启动工具.bat**（或命令行 `python 无线调试工具.py`）
2. 手机：**设置 → 开发者选项 → 无线调试**（保持开启）
3. 工具里选 **[1] 扫码配对**
4. 手机：**无线调试 → 使用二维码配对设备** → 扫电脑屏幕上的二维码
5. 配对成功后自动连接并入库，回到主菜单 —— 以后直接开工具就会自动连上

> **前提**：手机与电脑在同一个 WiFi；手机 Android 11 及以上。
> 终端二维码扫不动时，打开文件夹里的 `配对二维码.png` 扫。

**找不到「无线调试」开关？**
设置 → 关于手机 → 连点 7 次「版本号」开启开发者选项，再进 **设置 → 开发者选项 → 无线调试**。各品牌入口略有差异（小米在「更多设置」、OPPO/vivo 在「其他设置」），也可直接在设置里搜索「无线调试」。

## [7] 安装 APK：全屏拖放，拖进去就装

选中后终端会切成**全屏拖放界面**，然后用鼠标把 apk 文件从资源管理器**拖进窗口**即可，不需要敲命令。

```
  APK 拖放安装  ·  全屏模式                                  双击 Esc 退出
  ────────────────────────────────────────────────────────────────────────
  目标设备：V2520A  (192.168.3.15:39743)
  安装参数：adb install -r -d -t

  ╔══════════════════════════════════════════════════════════════════════╗
  ║                                                                      ║
  ║          把 APK 文件直接拖进本窗口 → 立刻安装到上面这台设备          ║
  ║                   也可以粘贴 / 输入路径，回车安装                    ║
  ╚══════════════════════════════════════════════════════════════════════╝
  最近安装：
  [√] app-debug.apk   12.3MB   安装成功   用时 18.4s
  $ adb.exe -s 192.168.3.15:39743 install -r -d -t "C:\app-debug.apk"
  √ app-debug.apk 安装完成（18.4s）
  拖入即装 · 回车=安装输入的路径 · [d]=换设备 · 双击 Esc 退出

  路径 >
```

**操作说明**

| 操作 | 效果 |
|---|---|
| 把 apk 文件**拖进窗口** | 立刻开始安装（拖放注入的路径带回车、或停顿时都会自动触发，两种都兼容） |
| 一次拖入**多个 apk** | 依次全部安装 |
| 粘贴 / 手动输入路径 + **回车** | 同样安装（支持带引号的路径、空格路径） |
| 安装过程中按 **Esc** | 取消本次安装（不会退出全屏模式） |
| **[d]**（输入框为空时） | 退出全屏，重新选择装到哪台设备 |
| **双击 Esc**（或双击 Ctrl+C） | 退出拖放模式 |
| 装完一个继续拖 | 不用退出，可以连着装好几个 |

**安装参数**：默认 `-r -d -t`（替换安装并保留数据 / 允许版本降级 / 允许测试包），可在 `config.json` 的 `apk_install_options` 里改，例如只想替换安装就填 `-r`。

### 不会一直卡在「正在安装」

装包时进度行会显示已用时间和上限：`正在安装 big.apk … 42.3s / 最长 300s（Esc 取消）`。三重保险，任何一种触发都会立刻掐掉 `adb install` 并在界面上写明原因：

| 情况 | 行为 |
|---|---|
| **总超时**：超过 300 秒还没装完 | 中止，提示 `安装超时中止`。大包 / 网速慢可调大（见下） |
| **设备掉线**：安装途中设备离线（Wi-Fi 断了、端口变了、手机锁屏断连）—— 这种 `adb install` 会一直挂着不返回 | 每 3 秒探一次，连续两次探测不到就中止，提示 `设备已离线，安装无法继续` |
| **手动取消**：安装中按 Esc | 立刻中止，提示 `已手动取消安装` |

超时时间默认 **300 秒**，两种改法：
- 菜单 **[8] ADB设置 → [7] 设置装包超时**（填秒数，`0` = 不限时）
- 或直接改 `config.json` 的 `"apk_install_timeout": 300`

> 只支持 `.apk` 文件；设备离线时会直接提示重新连接，不会静默失败。

## 关于「一台手机出现两个 adb 设备」的问题（已修复）

以前可能出现这种情况：

```
===== 断开设备 =====
[1] 192.168.3.15:39743  (device)
[2] adb-10CG7A0HBU004ZL-L0v0i0._adb-tls-connect._tcp  (device)
```

两个条目其实是**同一台手机**。原因不在本工具，而在 adb 自己：

- 新版 adb 的服务端默认会**自动连接**局域网里广播 `_adb-tls-connect._tcp` 的已配对设备（`ADB_MDNS_AUTO_CONNECT` 默认为 `adb-tls-connect`），于是多出一条以 mDNS 实例名命名的传输 `adb-XXX._adb-tls-connect._tcp`；
- 本工具自己又用 `adb connect IP:端口` 建了一条；
- 两条传输指向同一台手机 → `adb devices` 里就是两条，多设备场景下 `adb shell` 还会要求 `-s` 指定。

**修复办法（本工具已内置，无需手动操作）：**

1. **从根上关掉**：让 adb 服务在 `ADB_MDNS_AUTO_CONNECT=0` 的环境下启动（该变量由 adb 服务端进程读取，所以工具启动时会检测：服务是自己拉起的就直接生效，是别的工具起的就静默重启一次让它生效）。`adb mdns services` 服务发现不受影响，本工具的自动发现照常工作。
2. **自动清理**：每次进「连接 / 设备列表 / 断开 / shell / 装 APK」以及连接成功后，都会自动清掉多余的 mDNS 传输和同一台手机遗留的 `offline` 旧端口记录（会先确保 IP:端口 那条存在，不会把设备弄丢）。

想还原 adb 原生行为：菜单 **[8] ADB设置 → [6]**，或把 `config.json` 里 `disable_mdns_autoconnect` 改成 `false`。

## 菜单说明

| 菜单 | 说明 |
|---|---|
| [1] 扫码配对 | 电脑显示二维码+配对码，手机扫码；配对成功后**直接自动连接**并回到主菜单 |
| [2] 手动配对 | 手机「使用配对码配对设备」弹窗里的 `IP地址:端口` + 6 位配对码 |
| [3] 连接设备 | **只有一台设备时直接自动连接**；多台时列出自动发现(mDNS) 与设备库供选择，也可手动输入 `IP:端口` |
| [4] 设备列表 | `adb devices -l`，显示在线 / 离线 / 未授权状态和设备型号 |
| [5] 断开设备 | **只有一台设备时直接断开**；多台时任选一台或全部断开 |
| [6] 设备库管理 | 给设备重命名；**删除时会先 `adb disconnect` 再删记录**（当作陌生设备） |
| [7] 安装 APK | 全屏拖放模式，把 apk 拖进窗口即安装（带超时 / 掉线自动中止 / Esc 取消），双击 Esc 退出 |
| [8] ADB 设置 | 自动检测 / 手动输入 / 文件浏览器选择 adb.exe；查看版本；重启服务；**下载官方 platform-tools**；开关 mDNS 自动连接；设置装包超时 |
| [9] adb shell | **只有一台在线设备时直接进入**；连按两次 Esc（或两次 Ctrl+C）退出 |

> 旧版本的 **[7] USB 转无线**（`adb tcpip 5555`）已移除：它只适用于 USB 连接 + 固定 5555 端口的旧方案，跟本工具主打的 Android 11+ 无线调试（mDNS）不是一路，留着反而绕。

## 自动化行为

- **启动自动连接**：启动时开一个后台守护线程扫描设备库中的设备，主线程照常显示菜单，
  不会阻塞你的操作。**扫不到设备时不输出任何提示**；连上了才打印一行
  「√ 已自动连接：设备名 IP:端口」，并把你正等着的 `请选择 >` 提示符重新画回，两个都不会丢。
- **端口智能处理**：无线调试的端口每次开关都会变，连接时优先用 mDNS 实时发现的端口，
  mDNS 没有才回退到历史地址。
- **配对后直接连接**：菜单 [1]/[2] 配对成功后不再询问，直接连接并回到主菜单。
- **删除即断开**：菜单 [6] 删除设备时，先断开它的现有连接再删除记录（当作陌生设备处理）。
- **一台设备一条记录**：见上一节。
- **退出自动清理**：选 [0] 退出、Ctrl+C 中断、**点窗口右上角 X 关闭**三种方式都会先通知后台线程停止，
  再执行 `adb kill-server`（窗口 X 关闭通过控制台关闭事件捕获，清理只执行一次）。

以上行为可在 `config.json` 中调整（首次运行自动生成）：

```json
{
  "adb_path": null,                    // 自定义 adb.exe 路径，null = 自动检测
  "autoconnect_on_start": true,        // 启动时后台自动连接已配对设备
  "kill_adb_on_exit": true,            // 退出时清理 adb 后台进程
  "disable_mdns_autoconnect": true,    // 禁用 adb 自带的 mDNS 自动连接（防止一台手机两条记录）
  "apk_install_options": "-r -d -t",   // [7] 装 APK 时传给 adb install 的参数
  "apk_install_timeout": 300           // [7] 单次装包最长等待秒数，0 = 不限时
}
```

## ADB 位置说明（可自主选择）

程序按以下顺序自动查找 adb，也可随时在 **[8] ADB 设置** 里自己指定：

1. 你在 [8] 里手动指定过的路径（保存在 `config.json`）
2. 本文件夹内置的 `platform-tools\adb.exe`（Google 官方，开箱即用）
3. 系统 PATH 里的 adb
4. Android Studio 等常见安装位置

**没带 platform-tools 也能用**：菜单 **[8] → [5] 下载官方 platform-tools**，会自动从 Google 官方地址下载并解压到本工具目录，直接内置一份 adb。

## 常见问题

**Q：扫码配对一直等待超时？**
- 确认手机「无线调试」总开关是开的，并已点进「使用二维码配对设备」完成扫码
- 确认手机与电脑在同一 WiFi（注意手机别开 VPN / 代理）
- 电脑防火墙放行 adb（mDNS 发现需要 UDP 5353 端口）
- 可先用菜单 [8] → [4] 重启 adb 服务再试

**Q：配对成功但连接失败 / 设备连不上？**
- 无线调试端口每次开关都会变，用菜单 [3] 的「自动发现」重连即可
- 手机 IP 变了（DHCP 重新分配）时历史地址会失效，同样用 [3] 自动发现

**Q：还是看到两条设备记录？**
- 先进一次菜单 [4]（设备列表）或 [5]（断开设备），工具会自动清理多余记录
- 如果反复出现，说明有别的工具（如 Android Studio）在用它自己的 adb 服务，可先用菜单 [8] → [4] 重启 adb 服务，再确认 [8] 里显示「mDNS 自动连接：已禁用」

**Q：拖放没反应 / 装不上？**
- 拖放是把文件路径注入到控制台输入里，请拖到**控制台窗口内部**，且使用 Windows 自带的控制台 / Windows Terminal 运行（不要拖到 IDE 的输出面板）
- 拖不动时可以直接把路径粘贴进去后回车，效果一样
- 一次装多个也可以：拖入多个 apk 会依次安装

**Q：装 APK 一直卡在「正在安装」不动？**
- 默认 **300 秒**会超时中止；安装过程中直接按 **Esc** 可以立刻取消
- 如果最后提示的是「设备已离线，安装无法继续」，说明装包途中手机掉线了（Wi-Fi 断了 / 无线调试端口变了 / 手机长时间锁屏），回主菜单 [3] 重连后再装即可
- 如果是包太大或 Wi-Fi 太慢、真的需要更久，按 **[8] ADB设置 → [7] 设置装包超时** 调大（例如 900 秒），或填 `0` 不限时

**Q：二维码支持哪些工具扫？**
- 只能用手机系统设置里的入口扫（无线调试 → 使用二维码配对设备），微信 / 相机扫了没有用。

**Q：启动时自动连接会干扰我的终端操作吗？**
- 不会。扫描在后台守护线程里静默进行，扫不到不会输出任何东西。连上后打印一行连接提示，
  原来等你输入的 `请选择 >` 提示符会自动补画回来，菜单、提示和你的输入三者都不会乱。
  在全屏拖放模式里，后台消息也不会把画面打乱（会先排队，重画时显示）。
  不想自动连就把 `config.json` 里的 `"autoconnect_on_start"` 改成 `false`。

**Q：工具启动时重启了 adb 服务，会不会影响别的程序？**
- 只在检测到「已经有一个别的工具起的 adb 服务」时重启一次，目的是让「禁用 mDNS 自动连接」生效。
  重启会断开当前的无线连接，随后本工具的自动连接会把设备库里记住的设备重新连上（USB 设备不受影响）。
  不想要这个行为，就把 `"disable_mdns_autoconnect"` 改成 `false`。

**Q：点窗口右上角的 X 关闭，adb 会被清理吗？**
- 会。程序注册了 Windows 控制台关闭事件，点 X 关闭时同样会执行 `adb kill-server`。
  如果确实不希望清理，把 `config.json` 里 `"kill_adb_on_exit"` 改成 `false`。

**Q：退出时 adb 被关掉了，其他正在用 adb 的工具受影响吗？**
- `adb kill-server` 会停掉 adb 服务，其他工具下次调用 adb 时会自动重新拉起，不受影响。
